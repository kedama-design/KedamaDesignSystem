# 提案：`tailwind-merge` を本番依存に追加するか

作成日: 2026-08-02 / **結論：見送り（追加しない）**

> ## 判断（2026-08-02・確定）
>
> **`tailwind-merge` は追加しない。** 理由は3つ。
>
> 1. 導入根拠だった「上流との黙ったフォーク」が、実測（§3.2）で成立していない
> 2. 唯一の競合は取り込み品ではなく自作の Button ghost 由来（§3.3-2）なので、
>    依存を足さずに発生源を断てる
> 3. `extendTailwindMerge` の設定（§4）がトークンから乖離したとき、静かに誤って
>    マージされる。silent failure を1つ減らすために別の silent failure を1つ
>    増やす取引になる
>
> **代わりに行ったこと**
>
> - Button の ghost から既定文字色を外した（上流 shadcn の ghost と同形）。
>   競合の発生源そのものが消えた
> - 外した結果 ghost の文字色は継承になり、実測で純黒 `rgb(0,0,0)` に落ちた。
>   Kedama に純黒は無いため、原因である「`@layer base` に既定文字色が無い」
>   ことを修正した。修正後は `rgb(4,3,2)` = `fg.default` に解決する
> - `tests/classConflict.test.ts` で**競合そのものを禁じた**。Tailwind 本体の
>   `compile()` で CSS を生成し、同じ (バリアント, プロパティ) を2つ以上の
>   クラスが設定していたら落ちる。ghost に文字色を戻すと実際に落ちる
>
> **再検討の合図**：上のテストが落ちたとき。とくに「消せない競合」が
> 取り込み品どうしで生じた場合は、本書に戻ること。

新しい本番依存を追加する際の手順（用途・URL・ライセンス・bundle 影響・既存代替）に従う。

---

## 1. 用途

`src/lib/cn.ts` は現在 clsx のみ:

```ts
export function cn(...inputs: ClassValue[]): string {
  return clsx(inputs);
}
```

上流 shadcn/ui の `cn` は `twMerge(clsx(inputs))` であり、**後から渡したクラスが
同じ CSS プロパティを触る先行クラスを打ち消す**というセマンティクスを持つ。
取り込んだコードはこの前提で書かれているため、`cn` がそれを持たないと
取り込み品が上流と異なる挙動をしうる。

## 3. §2.1.5 の観点での評価（本命の論点）

「取り込み品が上流と異なる挙動をする」＝ 構造・挙動のフォークに該当するか。

### 3.1 機構が実在することの実測

ブラウザで実際に測った（クラス名の並び順ではなく解決値）:

| 与えたクラス | 実測 `padding-left` |
| ------------ | ------------------- |
| `px-4`       | 16px                |
| `px-4 px-2`  | **16px**            |
| `px-2 px-4`  | **16px**            |

**順序に関係なく `px-4` が勝つ。** clsx は文字列を連結するだけなので、勝敗は
class 属性の順序ではなく**生成 CSS の順序**で決まる。上流（twMerge あり）なら
どちらの順序でも後から渡した `px-2` が勝つ。ここが上流とのセマンティクス差。

### 3.2 では、いま実際に挙動が変わっている箇所はあるか → **無い**

取り込み済み7ファイル（accordion / drawer / sheet / skeleton / spinner / table /
toast）で、同一 CSS プロパティを触るクラスが同じ要素に重なる箇所を洗い出した:

| 箇所                          | 重なり                                                                  | 結果                         |
| ----------------------------- | ----------------------------------------------------------------------- | ---------------------------- |
| `ToastClose`                  | `text-muted-foreground` を Button の ghost（`text-fg-default`）に重ねる | **muted が勝つ＝上流と同じ** |
| `ToastAction`                 | `shrink-0` が Button の `shrink-0` と重複                               | 同一クラスなので差が出ない   |
| `SheetContent` の閉じるボタン | `absolute top-3 right-3` を Button に重ねる                             | Button 側に競合クラス無し    |

実測:

| 与えたクラス                            | 実測 `color`     |
| --------------------------------------- | ---------------- |
| `text-fg-default`                       | rgb(4,3,2)       |
| `text-muted-foreground`                 | rgb(75,71,61)    |
| `text-fg-default text-muted-foreground` | rgb(75,71,61) ✅ |
| `text-muted-foreground text-fg-default` | rgb(75,71,61) ✅ |

**結論：現時点で上流と挙動が変わっている取り込み品は無い。**
唯一の実質的な競合（ToastClose の文字色）は、生成 CSS の順序がたまたま
twMerge と同じ結果を返している。

### 3.3 ただし2点

1. **「たまたま」である。** 勝敗は Tailwind の生成順に依存しており、ユーティリティの
   追加や Tailwind の更新で静かに反転しうる。反転しても型でもテストでも落ちない
2. **この競合は取り込み品ではなく Kedama 側が作った。** 上流の ghost は文字色を
   持たない（`hover:text-foreground` のみ）。統合 Button で `text-fg-default` を
   ghost の既定に足したために競合が生まれた。tailwind-merge を入れない場合の
   代替として、**ghost から既定文字色を外す**（上流と同形にする）選択肢がある

## 4. 導入した場合の既知のコスト

tailwind-merge v3 の既定設定は **Tailwind v4 の既定テーマ名前空間**を前提にしている。
Kedama の独自ユーティリティは既定設定では認識されない（v3.6.0 のソースで確認）:

| Kedama の指定                                | tailwind-merge 既定の判定                                   | 影響                           |
| -------------------------------------------- | ----------------------------------------------------------- | ------------------------------ |
| `bg-accent-primary` 等の独自セマンティック色 | `theme.color: [isAny]` → **認識される**                     | 問題なし                       |
| `px-4` / `size-8` 等                         | `theme.spacing: ['px', isNumber]` → 認識される              | 問題なし                       |
| `duration-fast` / `normal` / `slow`          | `duration: [isNumber, 'initial', …]` → **認識されない**     | 同グループとして打ち消されない |
| `ease-default` / `enter` / `exit`            | `ease: ['linear','initial',themeEase,…]` → **認識されない** | 同上                           |

`duration-*` / `ease-*` は Kedama が `@utility` と `@theme` で独自に定義したもの
（Tailwind v4 に duration の名前空間が無いため）。導入するなら
`extendTailwindMerge` でこの2グループを教える設定が要る。**設定後は実測で確認する**
（`duration-fast duration-200` が正しく後勝ちになるか）。

## 5. 既存の代替

| 代替                               | 評価                                                                                                                                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 現状維持（clsx のみ）              | 競合を作らない書き方（衝突するユーティリティを base と variant に分散させない）で回避する。統合 Button は実際にこの方針で書いた。ただし**取り込み品には適用できない**（上流のコードだから） |
| `cva` の `compoundVariants` で吸収 | コンポーネント内部の競合には効くが、`cn(literal, className)` の外部からの上書きには効かない                                                                                                 |
| ghost から既定文字色を外す         | 3.2 の唯一の競合はこれで消える。ただし将来の取り込みで別の競合が出れば同じ議論になる                                                                                                        |
| 自前で最小の打ち消し実装           | 非推奨。Tailwind のクラスグループ表を自前で持つことになり、上流追従のコストが tailwind-merge より高い                                                                                       |

## 6. 評価

**追加する理由になるもの**

- 上流 shadcn は twMerge セマンティクス前提で書かれており、それを持たないことは
  §2.1.5 が禁じる「挙動のフォーク」に**将来該当しうる**。しかも黙って起きる
- 取り込みは今後も続く（Q4 の低層部品、Tier 2 の AppShell / DataTable / Command）。
  取り込み量に比例して競合の機会が増える
- コストが小さい（8.8 KB gzip / 依存 0 / MIT / sideEffects false）

**追加しない理由になるもの**

- **現時点で実害が観測されていない**（3.2）
- 独自の `duration-*` / `ease-*` のために設定と、その設定の実測検証が要る（4）
- §2.2 の「必要になったコンポーネントから都度追加し、依存を先取りしない」方針と
  素直には整合しない

**追加理由に数えていないもの**：「consumer が `className` で上書きできない」こと。
画面ごとの手当てを減らして props / variant に寄せるのが本基盤の趣旨であり、
上書きしにくいことは欠点ではない。この観点は評価から外している。

## 7. 判断（ユーザー）

- [ ] 追加する（`^3.6.0` を `dependencies` へ。`extendTailwindMerge` で
      `duration-*` / `ease-*` を登録し、実測で確認する）
- [x] **今は追加しない（ghost の既定文字色を外して 3.2 の競合を消す）** ← 採用
- [ ] 追加しない（現状維持。競合が実害を出した時点で再検討）
